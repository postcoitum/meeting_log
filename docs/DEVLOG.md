## 2026-06-22 — 회의록 데스크톱 앱 MVP

### 배경
원래 이 프로젝트는 녹음 파일을 받아 **전사 + 화자분리**해주는 CLI 도구(`meeting_recorder.py`)였다.
이걸 스크린샷으로 본 "Alt" 같은 **데스크톱 GUI 앱**으로 키우기로 했다.

### 1. CLI 안정화 (선행 작업)
앱으로 넘어가기 전에 CLI부터 제대로 돌게 고쳤다.
- **pyannote 4.x 대응**: 화자분리 결과가 dict에서 `DiarizeOutput` 데이터클래스로 바뀐 문제 수정
- **전사 엔진 교체**: 실시간 스트리밍 방식(Lightning-SimulWhisper)이 무음 구간에서 같은 말을
  무한 반복(`뭐야? 뭐야? …`)하고 느렸다 → **배치 방식 mlx-whisper(`large-v3-turbo`)**로 교체.
  반복이 사라지고 속도도 크게 빨라졌다(10분 오디오 추론 ~25초).
- **화자 수 유연화**: 자동 감지(기본) / `--speakers N` 고정 / `--max-speakers M` 상한 지원.
  이름을 안 주면 `화자 1`, `화자 2`로 자동 라벨링해 완전 비대화형 실행.

### 2. 앱 설계
- **틀**: pywebview + Python 단일 백엔드 + 가벼운 웹 프론트 (언어를 Python 하나로 모아 유지보수 단순화)
- **레이아웃(4영역 글래스, 브라운베이지톤)**:
  좌측 회의 목록 · 중앙 로컬 AI 요약(마크다운 편집) · 우측 상단 내 메모 · 우측 하단 스크립트 원본
- **저장**: 로컬 SQLite 1파일 (외부 전송 없음)
- **요약**: 로컬 LLM(mlx-lm, `Qwen2.5-3B-Instruct-4bit`)

설계 문서: `docs/superpowers/specs/2026-06-21-meeting-app-design.md`
구현 계획: `docs/superpowers/plans/2026-06-21-meeting-app.md`

### 3. 구현 (TDD, 10단계)
기존 CLI 로직을 최대한 재사용하며 작업을 잘게 나눠 진행했다. 각 단계마다 테스트→구현→커밋.
1. 앱 골격 + 빈 pywebview 창
2. SQLite 저장 모듈 (CRUD)
3. 전사 래퍼 (기존 CLI 파이프라인 재사용)
4. 로컬 AI 요약 모듈
5. pywebview 브릿지 API
6. 4영역 글래스 레이아웃
7. 화면 로직 (목록·편집·자동저장)
8. 네이티브 파일 선택
9. 전사 진행 상태 표시
10. 문서 정리 (이 일지 포함)
