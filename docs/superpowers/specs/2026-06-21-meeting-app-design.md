# 로컬 회의록 데스크톱 앱 — 설계 문서

작성일: 2026-06-21
상태: 승인됨 (구현 계획 대기)

## 1. 개요

기존 CLI 도구(`meeting_recorder.py`)를 **데스크톱 GUI 앱**으로 발전시킨다.
녹음 파일을 올리면 전사·화자분리하고, 로컬 AI로 요약을 생성하며, 사용자가
요약·메모를 직접 편집하고 회의들을 목록으로 관리한다. 모든 처리와 저장은
**로컬**에서 이뤄진다(데이터 외부 유출 없음).

참고 UI: 사용자가 제시한 "Alt" 앱 스크린샷 (3단 레이아웃, 글래스 느낌).

## 2. MVP 범위

### 포함
- 오디오 파일 업로드 → 전사(mlx-whisper) + 화자분리(pyannote)
- 로컬 LLM(mlx-lm)으로 회의 요약 생성
- 요약을 마크다운으로 직접 편집/추가
- 별도 메모 칸(마크다운)
- 전사 스크립트 원본 보기
- 회의 목록 관리(날짜별 정렬, 제목 수정)
- 로컬 SQLite 저장
- 패널 접기(사이드바, 메모)

### 제외 (향후 단계)
- 실시간 마이크 전사
- AI 퀴즈/채팅/번역
- 화자별 점유율 그래프, 주요 발언 카드
- 슬라이드 생성
- 클라우드 동기화

## 3. 화면 레이아웃

```
┌─ 상단바: ●●● [사이드바 토글]  회의록 앱 ────────────────────┐
├──────────┬──────────────────┬──────────────────────────┤
│ 회의 목록  │   회의 요약        │   내 메모 (접기)            │
│ (날짜별)   │   (로컬 AI +       │   직접 작성, 마크다운       │
│          │    마크다운 편집)   ├──────────────────────────┤
│ [연필=제목 │                   │   스크립트 원본             │
│  수정]    │                   │   (전사 전체 텍스트)        │
│ + 새 회의  │                   │                          │
└──────────┴──────────────────┴──────────────────────────┘
```

- **상단바**: 윈도우 컨트롤 옆에 사이드바 토글 버튼 (좌측 패널 접기/펼치기)
- **좌측 — 회의 목록**: 날짜별 그룹, 헤더에 제목 수정 연필 버튼 1개(선택된 회의 제목 편집), 하단에 `+ 새 회의`
- **중앙 — 회의 요약**: 로컬 AI가 생성, 마크다운으로 직접 수정/추가
- **우측 상단 — 내 메모**: 사용자가 자유롭게 작성(마크다운), 접기 버튼
- **우측 하단 — 스크립트 원본**: 전사된 전체 텍스트(시간 포함)

### 디자인
- **브라운베이지톤 배경 + Liquid Glass(반투명 + 블러) 패널**
- OS 바탕화면을 실시간으로 비추는 진짜 vibrancy는 pywebview에서 보장이 어려우므로,
  앱이 은은한 브라운베이지 배경을 깔고 그 위에 frosted glass 패널을 얹는 방식
- 향후 사용자가 배경 이미지를 지정해 색감을 바꿀 수 있도록 여지를 둔다

## 4. 기술 스택

| 구성 | 선택 | 이유 |
|------|------|------|
| 앱 셸 | **pywebview** (macOS WKWebView) | Python 단일 스택 유지, Electron보다 가벼움 |
| 백엔드 | **Python** | 기존 `meeting_recorder.py` 로직 재사용 |
| 전사 | **mlx-whisper** (`large-v3-turbo`) | 이미 검증됨, Metal 가속 |
| 화자분리 | **pyannote.audio** `speaker-diarization-3.0` | 이미 검증됨 |
| 요약 LLM | **mlx-lm** + `Qwen2.5-3B-Instruct`(기본) | 로컬·한국어 요약 품질 양호·가벼움 |
| 프론트엔드 | 가벼운 웹(HTML/CSS/JS) + 마크다운 렌더 | 빌드 최소화, 유지보수 단순 |
| 저장 | **SQLite** 단일 파일 | 로컬·백업 쉬움 |

> 언어를 Python 하나로 모아 유지보수를 단순화하는 것이 핵심 원칙.

## 5. 데이터 모델 (SQLite)

```
meetings
  id           INTEGER PK
  title        TEXT          -- 사용자가 편집 가능
  created_at   TEXT          -- 회의 날짜(ISO)
  audio_path   TEXT          -- 원본 경로(복사하지 않고 참조)
  transcript   TEXT          -- 전사 스크립트 원본(화자/시간 포함)
  summary_md   TEXT          -- 로컬 AI 요약(마크다운, 편집됨)
  memo_md      TEXT          -- 사용자 메모(마크다운)
  updated_at   TEXT
```

- 오디오 원본은 **경로만 저장**(앱이 파일을 복사·보관하지 않음 → 용량 절약)
- 단일 `meetings.db` 파일에 모든 회의 저장

## 6. 사용 흐름

1. `+ 새 회의` 클릭 → 오디오 파일 선택
2. 백그라운드로 전사(진행률 표시) → 화자분리 → 스크립트 생성
3. 스크립트로 로컬 AI 요약 생성 → 중앙에 표시
4. 목록에 새 회의 추가(파일명/날짜 기반 기본 제목)
5. 사용자가 제목 수정, 요약·메모 편집 → 입력 즉시 **자동 저장**
6. 목록에서 다른 회의 클릭 → 해당 내용 로드

## 7. 컴포넌트 분해

### 백엔드 (Python)
- `transcription`: 기존 `meeting_recorder.py`의 전사+화자분리 로직을 함수로 추출/재사용
- `summarizer`: mlx-lm으로 스크립트 → 마크다운 요약 생성
- `store`: SQLite CRUD (회의 생성/조회/수정/삭제)
- `api`: pywebview JS↔Python 브릿지 (프론트가 호출하는 함수들: 새회의, 목록, 저장 등)

각 모듈은 독립적으로 테스트 가능해야 한다.
- 전사: 오디오 경로 → 스크립트(순수 함수에 가깝게)
- 요약: 텍스트 → 마크다운(LLM 호출 격리)
- 저장: DB 입출력만 담당

### 프론트엔드 (웹)
- 레이아웃 셸(4영역 + 상단바 토글)
- 회의 목록 컴포넌트(날짜 그룹, 선택, 제목 편집)
- 마크다운 에디터/뷰어(요약·메모 공용)
- 스크립트 뷰어
- 진행률/로딩 표시

## 8. 에러 처리

- 전사 실패(잘못된 오디오, ffmpeg 없음 등) → 사용자에게 명확한 메시지, 목록에 빈 회의 안 만듦
- 요약 LLM 실패/모델 미다운로드 → 요약 영역에 "요약 생성 실패, 다시 시도" + 전사·메모는 정상 사용 가능(요약은 부가 기능이므로 전체를 막지 않음)
- DB 쓰기 실패 → 저장 실패 표시, 사용자 입력 유실 방지(재시도)
- HF 토큰 없음/모델 게이트 → 설정 안내(기존 CLI Troubleshooting 재사용)

## 9. 테스트 전략

- 백엔드 모듈별 단위 테스트(저장 CRUD, 요약 입출력 형식, 전사 래퍼)
- 짧은 샘플 오디오로 전사→요약→저장 통합 스모크 테스트
- 프론트는 핵심 상호작용(새 회의, 편집 자동저장, 회의 전환) 수동 확인

## 10. 향후 단계 (참고)

실시간 마이크 전사 → 화자 점유율/주요 발언 → 번역 → 퀴즈/채팅.
각 단계는 별도 설계·계획 사이클로 진행한다.
